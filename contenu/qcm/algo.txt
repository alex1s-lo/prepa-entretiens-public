# QCM des fiches d'algorithmique et de code (contenu/algo.txt).

=== algo-achat-vente-une-fois
+ Un seul passage en retenant le plus bas prix vu jusque-là : $O(n)$
  Le meilleur gain vendant au jour $i$ vaut $p_i - \min_{j \le i} p_j$ ; mémoire $O(1)$.
- Acheter au minimum global de la série, vendre à son maximum global
  Le maximum peut précéder le minimum.
- Tester toutes les paires : $O(n^2)$, c'est optimal
  Correct mais pas optimal.
- Trier les prix puis prendre le plus grand écart : $O(n \log n)$
  Le tri détruit l'ordre chronologique, essentiel ici.

=== algo-kadane
+ Meilleure somme finissant en $i$ $= \max(x_i,\ x_i + \text{précédente})$
  Algorithme de Kadane, en $O(n)$ ; on garde aussi le meilleur global vu.
- Faire la somme de tous les éléments positifs de la liste
  Le sous-tableau doit être contigu.
- Tester tous les sous-tableaux contigus et garder la meilleure somme : $O(n^2)$
  Correct mais lent.
- Le maximum de la liste moins son minimum, en un passage
  C'est une autre question (le meilleur trade).

=== algo-drawdown
+ Suivre le plus haut atteint et la pire baisse depuis ce sommet
  $O(n)$ ; le drawdown se mesure depuis le sommet **antérieur**.
- $(\max - \min)/\max$ sur toute la courbe, en un passage
  Le minimum peut précéder le maximum.
- La plus grande baisse d'un jour sur l'autre, en pourcentage
  Un drawdown s'étale sur plusieurs jours.
- L'écart-type des rendements quotidiens, annualisé par $\sqrt{252}$
  C'est la volatilité, pas le drawdown.

=== algo-two-sum
+ Un dictionnaire des valeurs déjà vues : $O(n)$
  Pour chaque $v$, on cherche $\text{cible} - v$ en $O(1)$.
- Double boucle
  $O(n^2)$, ce qu'on veut éviter.
- Trier puis deux pointeurs, en gardant les indices d'origine
  Correct en $O(n \log n)$ ; le dictionnaire fait mieux.
- Recherche binaire sur la liste non triée
  Elle exige une liste triée.

=== algo-moyenne-mobile
+ Somme glissante : ajouter l'entrant, retirer le sortant
  $O(n)$ : chaque prix est ajouté et retiré une seule fois.
- Recalculer la somme des $k$ prix à chaque nouvelle date
  Correct mais en $O(nk)$, pas $O(n)$.
- Garder la fenêtre triée et lire son milieu
  Ça donne la médiane glissante, pas la moyenne, et plus lentement.
- Moyenne de toute la série
  Ce n'est pas une moyenne mobile.

=== algo-mediane-flux
+ Deux tas : un tas max pour la moitié basse, un tas min pour la haute
  $O(\log n)$ par prix ; la médiane se lit au sommet des tas.
- Insérer chaque prix dans une liste triée et lire son milieu
  Correct mais $O(n)$ par insertion (décalage des éléments), contre $O(\log n)$ avec deux tas.
- Mettre à jour la moyenne courante à chaque prix, en $O(1)$
  Moyenne et médiane diffèrent.
- Une file qui garde les prix dans leur ordre d'arrivée
  Ne donne pas la médiane.

=== algo-reservoir
+ Garder le $i$-ième élément avec probabilité $1/i$
  Par récurrence, chaque élément reste avec probabilité $1/n$.
- Garder le dernier élément
  Pas uniforme.
- Tirer un indice au hasard au début
  On ne connaît pas la longueur.
- Garder chaque élément avec probabilité $1/2$
  Favorise les derniers éléments.

=== algo-melange
+ Fisher-Yates : échanger $i$ avec un $j \le i$ tiré uniformément
  La version « $j$ dans toute la liste » donne $n^n$ issues équiprobables, non divisible par $n!$ : les permutations ne peuvent pas être équiprobables.
- Trier par une clé aléatoire avec un comparateur aléatoire
  Un comparateur incohérent donne un mélange biaisé.
- Échanger chaque élément avec une position dans toute la liste
  C'est la version biaisée.
- Échanger avec n'importe quelle position, mais mélanger deux fois de suite
  Le nombre d'issues ($n^{2n}$) reste non divisible par $n!$ en général : le biais demeure.

=== algo-rand7
+ 25 valeurs par deux appels ; garder 21, sinon recommencer
  Échantillonnage par rejet : $5 \times (a-1) + b$ est uniforme sur 1..25 ; on prend le reste modulo 7.
- `rand5() + rand5() % 3`, qui couvre bien les valeurs de 1 à 7
  Non uniforme.
- Remettre à l'échelle : `rand5() * 7 // 5`, une seule fois
  Ne produit pas toutes les valeurs uniformément.
- Additionner deux `rand5()` et garder le reste modulo 7, plus 1
  La somme n'est pas uniforme.

=== algo-recherche-binaire
+ Le prix est croissant en $\sigma$ : on resserre un intervalle
  Robuste ; Newton (avec le vega) est plus rapide.
- Le prix est décroissant en $\sigma$ : on part d'un $\sigma$ élevé
  Il est croissant.
- On teste toutes les volatilités de 0 à 1 par pas fin
  Recherche linéaire, lente.
- La dichotomie ne marche que sur des entiers
  Elle marche sur toute fonction monotone.

=== algo-parentheses
+ Une pile : empiler les ouvrantes, vérifier à chaque fermante
  Pile vide à la fin.
- Compter les ouvrantes et les fermantes de chaque type
  `([)]` a les bons comptes mais est mal formée.
- Vérifier la symétrie de la chaîne
  `()()` n'est pas symétrique.
- Une file : on retire la première ouvrante à chaque fermante
  L'ordre doit être le dernier ouvert, premier fermé.

=== algo-mutable-defaut
+ `[1]` puis `[1, 2]`

- `[1]` puis `[2]`
  Ce serait le cas si la valeur par défaut était réévaluée.

=== algo-gil

  On contourne avec NumPy, des processus ou du code compilé ; les threads restent utiles pour les entrées-sorties.
- Le ramasse-miettes qui libère la mémoire des threads
  C'est un verrou.
- Un mécanisme qui répartit les threads sur tous les cœurs
  Il les sérialise.
- Une particularité de la machine virtuelle Java, absente de Python
  C'est une caractéristique de CPython.

=== algo-numpy-vectorisation
+ Des boucles en C sur des données contiguës et typées
  On évite l'interprétation objet par objet ; le broadcasting étend les dimensions sans copie.
- NumPy utilise plusieurs cœurs pour tout
  Pas forcément ; la vitesse vient surtout du code compilé.
- Le broadcasting copie les tableaux pour aligner les formes
  Il les étend virtuellement.
- Les boucles Python sont aussi rapides
  Elles sont typiquement 10 à 100 fois plus lentes.

=== algo-pandas-pieges
+ Alignement sur l'index, `shift` mal orienté, NaN, fuseaux horaires
  Tous produisent des erreurs sans message.
- pandas ne gère pas les dates : il faut tout convertir en texte
  Il les gère, avec des pièges.
- `shift(-1)` est sans danger pour les rendements futurs
  C'est précisément le regard vers le futur.
- Les NaN lèvent toujours une erreur, donc on les voit tout de suite
  Ils se propagent silencieusement.

=== algo-flottants
+ 0,1 n'est pas exact en binaire : comparer avec une tolérance
  Ou compter en centimes, ou utiliser `Decimal` ; l'erreur d'arrondi est de l'ordre de $10^{-16}$.
- Un bug de Python, corrigé dans les versions récentes
  C'est la norme IEEE 754.
- Passer en `float32`, plus prévisible pour les décimales
  Encore moins précis.
- Utiliser `==` après `round`
  Fragile au voisinage des arrondis.

=== algo-cpp-bases
? Pourquoi déclarer virtuel le destructeur d'une classe de base ?
+ Pour que `delete` via un pointeur de base détruise l'objet dérivé
  Sinon, comportement indéfini et fuite de ressources.
- Pour accélérer la destruction des objets alloués sur le tas
  Il ajoute une indirection.
- Pour interdire qu'on dérive de la classe de base
  C'est le rôle de `final`.
- Parce que tous les destructeurs doivent l'être
  Seulement pour les classes de base polymorphes.
